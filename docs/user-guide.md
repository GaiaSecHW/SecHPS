## 1. 整体流程概览

```
┌─────────────┐     ┌─────────────┐     ┌─────────────┐     ┌─────────────┐
│  创建智能体  │────▶│   创建任务   │────▶│   执行任务   │────▶│  查看结果   │
│  Agent App  │     │ TaskInstance │     │ CodeSwarm   │     │ 报告+漏洞   │
└─────────────┘     └─────────────┘     └─────────────┘     └─────────────┘
 上传 Agent 配置     选 Agent+模型       Worker 自动执行      漏洞统计分析
```

**核心概念：**

| 概念 | 说明 |
|------|------|
| **Agent App（智能体）** | 可复用的 AI Agent 运行时配置，包含引擎、Agent Harness 文件、启动命令等 |
| **TaskInstance（任务）** | 将智能体 + 模型 + 目标文件绑定在一起的执行单元 |
| **CodeSwarm Worker** | 分布式执行集群中的工作节点，负责实际运行 AI Agent |
| **Agent Harness** | 智能体的配置文件包（ZIP 压缩包），包含 agent 配置、技能定义等 |

## 2. 创建智能体（Agent App）

### 2.1 进入页面

导航至 **仪表盘 → 智能体应用**（`/dashboard/agent-apps`），点击「创建智能体」按钮。

### 2.2 填写表单

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| **应用名称** | 必填 | 智能体的显示名称 |
| **引擎类型** | 必填 | 选择执行引擎，见下方说明 |
| **租户** | 视权限 | 普通用户自动绑定当前租户；管理员/ICSL 用户可选择"公开共享"或指定租户 |
| **Agent Harness 文件** | 必填 | 上传包含 Agent 配置的压缩包（支持 ZIP / RAR / 7Z / tar.gz）或文件夹 |
| **默认 Agent 名称** | 必填 | 系统根据上传文件自动检测，也可手动输入 |
| **启动命令** | 可选 | Agent 启动时执行的命令（如 `/project:security-scan`） |
| **文件结构要求** | 可选 | 自然语言描述，系统会用 LLM 验证后续上传的任务文件是否符合要求 |

### 2.3 引擎类型说明

| 引擎 | 说明 | Agent Harness 要求 |
|------|------|-------------------|
| **opencode** | 使用 opencode-ai CLI 执行 | 压缩包内需包含 `opencode.json` 配置文件 |
| **claudecode** | 使用 Claude Code CLI 执行 | 压缩包内需包含 `.claude/agents/*.md` Agent 定义文件 |
| **agentflow** | 使用可视化流水线执行 | 支持流水线视图编辑 |

### 2.4 Agent Harness 文件结构示例

**opencode 引擎：**
```
agent-harness.zip
├── opencode.json          # Agent 配置（必须）
├── skills/                # 技能定义文件
│   └── security-scan.md
└── prompts/               # Prompt 模板
```

**claudecode 引擎：**
```
agent-harness.zip
├── .claude/
│   ├── agents/
│   │   └── security-scanner.md   # Agent 定义（至少一个）
│   └── CLAUDE.md                 # 项目指令
└── scripts/                      # 辅助脚本
```

### 2.5 创建成功后

- Agent Harness 文件会被上传至 MinIO 对象存储
- 系统自动从 Harness 中提取技能（Skills）信息
- 智能体状态变为 `active`，可在列表中查看和管理

## 3. 创建任务

### 3.1 进入页面

导航至 **仪表盘 → 任务构建器**（`/dashboard/task-builder`），点击「创建任务」按钮。

### 3.2 填写表单

| 字段 | 是否必填 | 说明 |
|------|----------|------|
| **产品名称** | 可选 | 选择目标产品（用于知识图谱匹配），通过树形选择器选取 |
| **任务名称** | 必填 | 任务的显示名称 |
| **任务描述** | 可选 | 任务的详细说明，会作为 Agent 的执行指令 |
| **选择 Agent** | 必填 | 勾选一个或多个已创建的智能体（支持多选） |
| **选择模型** | 必填 | 从下拉菜单中选择 AI 模型（不同模型配置的名称会分组显示） |
| **上传文件** | 可选 | 上传待分析的目标文件（支持 ZIP/JAR/WAR/PDF/DOC 等，最大 5GB） |

### 3.3 多 Agent 选择说明

- 选择多个 Agent 时，系统会为每个 Agent 创建一个独立的任务实例
- 所有任务共享同一份上传文件和 NFS 工作区
- 每个任务可独立执行和查看结果

### 3.4 文件结构验证

如果 Agent App 设置了「文件结构要求」，系统会在任务创建时使用 LLM 自动验证上传的文件结构是否符合要求。不符合时任务创建会失败并提示原因。

### 3.5 创建成功后

系统自动完成以下准备工作：
1. 在 NFS 共享存储中创建任务目录（`/{taskId}/`）
2. 从 MinIO 下载 Agent Harness 文件到任务目录
3. 解压用户上传的文件到任务目录
4. 创建 `pending` 状态的 `TaskInstance` 数据库记录

## 4. 执行任务

### 4.1 启动执行

在任务列表页面，点击任务对应的「执行」按钮。也可进入任务详情页点击「执行」。

### 4.2 执行流程

```
用户点击「执行」
       │
       ▼
  创建 CodeswarmTask（状态: queued）
       │
       ▼
  调度器选择最优 Worker ──────▶ Worker 离线？▶ 重新排队，等待其他 Worker
       │
       ▼
  Worker 接收任务（状态: dispatched）
       │
       ▼
  构建执行环境（状态: building）
  - 下载 Agent Harness
  - 配置 Agent 运行时
  - 启动知识图谱预处理（如适用）
       │
       ▼
  运行 AI Agent（状态: running）
  - Agent 分析目标文件
  - 调用工具执行操作
  - 实时流式输出日志
       │
       ▼
  执行完成（状态: completed / failed）
  - 解析漏洞报告
  - 提交漏洞记录到数据库
```

### 4.3 调度策略

- **最少负载优先**：调度器优先选择当前运行任务数最少的 Worker
- **指定 Worker**：可指定首选 Worker 节点（`preferredWorkerNodeId`）
- **健康检查**：90 秒无心跳的 Worker 自动标记为离线，其任务重新排队
- **超时保护**：运行超过 30 秒无响应的任务会被扫描并处理

### 4.4 实时状态

任务执行期间，任务详情页会实时更新以下信息：

- **Agent 执行阶段**：queued → dispatched → building → running → completed
- **运行时间计时器**
- **Agent 输出流**：以 Markdown 格式渲染的 Agent 输出
- **工具调用摘要**：每个工具的调用次数统计
- **错误信息**：实时显示异常

## 5. 查看任务结果

### 5.1 任务详情页

导航至 **仪表盘 → 任务构建器 → 点击任务名称**，进入任务详情页。

### 5.2 结果内容

| 区域 | 说明 |
|------|------|
| **状态信息** | 任务状态徽章、执行阶段、运行时间 |
| **执行结果** | Agent 的最终输出报告 |
| **漏洞统计** | 按严重等级（Critical / High / Medium / Low / Info）分类的漏洞数量 |
| **漏洞详情** | 点击可跳转至漏洞管理页面查看详细信息和处理建议 |
| **上传文件信息** | 显示本次任务上传的文件列表 |
| **技能和脚本** | 显示注入/合并到 Agent 的技能与脚本 |
| **执行日志** | 分组显示的完整执行日志，包含时间线 |

### 5.3 重新执行

如需重新运行任务，点击「重新执行」按钮。系统会清除上次的日志和结果，重新调度执行。

## 6. 附录

### 6.1 用户角色与权限

| 角色 | 访问范围 |
|------|----------|
| **Platform Admin** | 查看和管理所有数据，可设置智能体为"公开共享" |
| **ICSL 用户** | 查看所有数据 |
| **普通租户用户** | 仅查看本租户数据 + 公开数据 |

### 6.2 任务状态说明

| 状态 | 含义 |
|------|------|
| `pending` | 任务已创建，等待用户执行 |
| `running` | 任务正在 Worker 上执行 |
| `completed` | 任务执行成功完成 |
| `failed` | 任务执行失败 |

### 6.3 Worker 节点管理

管理员可在 **仪表盘 → CodeSwarm** 页面查看：
- Worker 节点状态（在线/离线）
- 当前运行任务数
- Worker 心跳信息
- 任务调试面板

### 6.4 快速开始步骤

1. **登录** — 使用管理员账号 `admin` / `admin123` 登录平台
2. **创建智能体** — 上传 Agent Harness ZIP 包，选择引擎类型，配置 Agent 名称
3. **创建任务** — 选择智能体和模型，上传待分析文件，填写任务描述
4. **执行任务** — 点击执行，在详情页实时查看运行状态
5. **查看结果** — 执行完成后查看报告和漏洞统计
