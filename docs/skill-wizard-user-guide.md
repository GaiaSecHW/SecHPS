# Skill 创建向导 - 使用指南

## 概述

Skill 创建向导是一个完整的引导式 Skill 创建工具，帮助用户从零开始创建高质量的 Claude Skill。整个流程包含 7 个步骤，覆盖了从意图捕获到描述优化的完整生命周期。

## 访问方式

1. 进入 **Skills 库** 页面 (`/dashboard/skills`)
2. 点击 **"引导式创建"** 按钮（紫色按钮）
3. 开始创建流程

## 完整流程

### 步骤 1: 捕获意图

**目标**: 明确你想创建什么样的 Skill

**填写内容**:
- **Skill 名称**: 使用英文小写和连字符，如 `sql-injection-detector`
- **简短描述**: 一句话说明 Skill 的作用
- **分类**: 选择最适合的分类（代码审计、认证鉴权等）
- **功能描述**: 详细说明 Skill 要做什么
- **触发时机**: 描述何时应该触发这个 Skill
- **期望输出**: 说明期望的输出格式和内容
- **是否需要测试用例**: 建议勾选，可以帮助验证效果

**示例**:
```
名称: sql-injection-detector
描述: 检测代码中的 SQL 注入漏洞
分类: 代码安全审计
功能: 分析代码中的 SQL 查询，识别字符串拼接、参数化查询缺失等安全问题
触发时机: 当用户上传后端代码文件或请求代码安全审计时
期望输出: 包含漏洞位置、代码片段、风险等级、修复建议的结构化报告
```

### 步骤 2: 调研访谈

**目标**: 收集更多细节信息

**填写内容**:
- **边缘情况**: 列出需要特别处理的特殊情况
- **输入输出格式**: 详细描述输入数据和期望输出
- **示例文件**: 提供示例文件路径（可选）
- **成功标准**: 定义 Skill 成功执行的标准
- **依赖项**: 列出需要的工具或资源

**示例**:
```
边缘情况:
- 大文件处理时内存溢出
- 空输入的处理
- 不支持的编程语言

输入输出格式:
输入: Java、Python、PHP 等后端代码文件
输出: JSON 格式报告，包含文件路径、行号、漏洞类型、风险等级

成功标准:
- 准确识别出所有 SQL 注入点
- 无漏报
- 提供可操作的修复建议

依赖项:
- read_file
- search_pattern
```

### 步骤 3: 生成 Skill

**目标**: AI 自动生成 Skill 定义，可手动调整

**操作**:
1. 点击 **"重新生成"** 按钮，AI 会根据前两步的信息生成 Skill
2. 查看生成的系统提示词和用户提示词
3. 可以手动编辑各个字段
4. 选择需要的工具
5. 可以复制为 Markdown 格式

**生成内容**:
- Skill 名称和显示名称
- 描述
- 系统提示词（定义角色和行为）
- 用户提示词（定义请求模板）
- 工具列表

### 步骤 4: 创建测试用例

**目标**: 创建测试用例验证 Skill 效果

**操作**:
1. 为每个测试场景创建一个测试用例
2. 填写测试名称和提示词
3. 可选：添加期望输出描述
4. 可选：关联测试文件

**建议**:
- 创建 2-5 个测试用例
- 覆盖不同的场景和边缘情况
- 包含清晰的期望输出

**示例测试用例**:
```
名称: 检测简单 SQL 注入
提示词: 请分析这段 Java 代码中的 SQL 注入漏洞：

String query = "SELECT * FROM users WHERE id = " + userId;

期望输出: 应该识别出字符串拼接导致的 SQL 注入漏洞
```

**注意**: 如果在步骤 1 选择了"不需要测试用例"，可以跳过此步骤。

### 步骤 5: 运行评估

**目标**: 测试 Skill 的实际效果

**操作**:
1. 点击 **"开始评估"** 按钮
2. 系统会对每个测试用例运行两次：
   - 一次使用你的 Skill
   - 一次不使用 Skill（作为基线对比）
3. 查看实时进度和结果
4. 等待所有测试完成

**结果展示**:
- 每个测试的运行状态（等待中、运行中、已完成、失败）
- 运行耗时和 Token 使用量
- 输出内容

### 步骤 6: 迭代改进

**目标**: 根据测试结果改进 Skill

**操作**:
1. 对比有 Skill 和无 Skill 的输出
2. 查看自动生成的改进分析
3. 在反馈框中输入你的想法
4. 点击 **"应用反馈"** 按钮
5. 系统会根据反馈优化 Skill
6. 可以点击 **"重新测试"** 验证改进效果

**迭代历史**:
- 记录每次迭代
- 显示改进内容和时间
- 支持多次迭代

### 步骤 7: 描述优化

**目标**: 优化 Skill 描述，提高触发准确性

**操作**:
1. 查看当前描述
2. 点击 **"开始优化描述"** 按钮
3. 系统会生成更详细的描述
4. 查看预估触发准确率
5. 对比原始描述和优化后描述
6. 点击 **"应用优化"** 使用优化后的描述

**优化内容**:
- 添加使用场景说明
- 包含触发关键词
- 描述适用范围

### 完成

**操作**:
1. 点击 **"完成创建"** 按钮
2. 系统会保存 Skill 到数据库
3. 自动跳转到 Skill 详情页面

## 后续操作

### 查看 Skill

- 在 Skills 列表查看新创建的 Skill
- 点击查看详情和 SKILL.md 预览
- 可以编辑、启用/禁用 Skill

### 编辑 Skill

- 进入 Skill 详情页
- 点击 **"编辑"** 按钮
- 修改字段后保存

### 测试 Skill

- 在项目中使用 Skill
- 观察实际效果
- 根据需要返回向导继续优化

## 技术细节

### 数据存储

- **会话期间**: 数据存储在 `sessionStorage`
- **刷新页面**: 自动恢复数据
- **完成后**: 自动清理临时数据

### API 调用

#### Skill 生成 API
```
POST /api/skills/generate
Body: { intent, research }
Response: { skill }
```

#### 测试运行 API
```
POST /api/skills/test-runs
Body: { testCase, skillData, runType }
Response: { output, duration, tokens }
```

## 常见问题

### Q: 可以跳过某些步骤吗？
A: 步骤 4（测试用例）可以选择跳过，其他步骤必须完成。

### Q: 可以返回修改之前的步骤吗？
A: 可以，使用 **"上一步"** 按钮随时返回。

### Q: 中途退出会丢失数据吗？
A: 不会，数据会自动保存在 sessionStorage，刷新页面后恢复。

### Q: 生成的 Skill 可以手动编辑吗？
A: 可以，在步骤 3 可以编辑所有字段。

### Q: 如何查看 Skill 的 Markdown 格式？
A: 在步骤 3 点击 **"复制为 Markdown"** 按钮。

### Q: 测试失败怎么办？
A: 查看失败原因，修改 Skill 定义后重新测试。

### Q: 迭代改进有限制次数吗？
A: 没有限制，可以持续改进直到满意。

## 最佳实践

1. **详细的意图描述**: 步骤 1 和 2 越详细，生成的 Skill 质量越高
2. **多写测试用例**: 覆盖更多场景，提高 Skill 可靠性
3. **持续迭代**: 根据实际使用效果不断改进
4. **优化描述**: 好的描述能提高触发准确性
5. **保存迭代历史**: 记录每次改进的原因和效果

## 故障排查

### Skill 生成失败
- 检查网络连接
- 查看控制台错误日志
- 刷新页面重试

### 测试运行超时
- 减少测试用例数量
- 简化测试提示词
- 检查后端服务状态

### 数据丢失
- 检查浏览器是否禁用了 sessionStorage
- 避免使用隐私模式
- 及时完成创建流程
