## 第一章 平台概述

### 1.1 产品定位

SecHPS 是新一代 **AI 驱动的智能代码安全审计平台**，融合了：

- **大语言模型深度分析** - 基于 Claude/GPT 等先进 AI 模型
- **知识图谱自动进化** - Skill 精准率自适应优化
- **闭环反馈机制** - 从失败中学习，持续提升检测能力
- **可视化工作流编排** - DAG/FSM 双模式评估引擎

### 1.2 核心能力矩阵

| 能力维度 | 技术实现 | 业务价值 |
|---------|---------|---------|
| **智能检测** | 150+ 预置 Skills + AI 动态生成 | 覆盖 OWASP Top 10 + CWE 常见漏洞 |
| **精准进化** | 10 次重试 + 回测验证机制 | 误报率降低 50%+ |
| **知识传承** | Autonomous Experience 自主学习 | 跳过重复失败，效率提升 30%+ |
| **权限管控** | RBAC 5 级角色体系 | 细粒度权限，安全合规 |

## 第三章 项目管理

### 3.1 创建项目

**操作步骤**：

1. 进入 **[项目管理]** 页面
2. 点击 **[+ 新建项目]** 按钮
3. 填写项目信息：
   - 项目名称（必填）
   - 技术栈选择（下拉多选）
   - 项目描述（可选）
4. 上传项目文件：
   - 支持格式：`.zip`, `.tar.gz`, 单文件
   - 最大体积：100MB
5. 点击 **[创建]** 完成

**最佳实践**：
- ✅ 建议上传完整源码包，而非单个文件
- ✅ 技术栈选择准确可提升 Skill 匹配精准度
- ✅ 项目名称建议包含版本信息（如 `myapp-v2.1`）

### 3.2 启动安全评估

**评估配置**：

1. 在项目卡片上点击 **[启动评估]**
2. 选择评估模式：
   - **DAG 模式**：适用于全面审计，节点拓扑执行
   - **FSM 模式**：适用于深度分析，状态机循环迭代
3. 选择工作流：
   - 预置工作流：`Full Audit`, `Quick Scan`, `Auth Focus`
   - 自定义工作流：用户创建的可复用流程
4. 选择 AI 模型：
   - Claude 系列：`claude-3-opus`, `claude-3-sonnet`
   - OpenAI 系列：`gpt-4`, `gpt-4-turbo`
   - Gemini 系列：`gemini-pro`
5. 点击 **[开始评估]**

**评估执行流程**：

```
准备阶段 → 文件解析 → Skill 选择 → 执行检测 → 漏洞记录 → 报告生成
    │          │          │          │          │          │
  5秒       10秒       自动       流式      实时      完成
```

### 3.3 查看评估结果

**实时监控**：

- **进度条**：显示当前执行阶段
- **日志流**：SSE 实时推送 AI 分析过程
- **漏洞列表**：检测到漏洞即时展示

**评估报告**：

1. 点击项目卡片的 **[查看报告]**
2. 报告结构：
   - **项目概况**：架构图、入口点、认证鉴权
   - **漏洞汇总**：按类型/严重程度统计
   - **详细发现**：每个漏洞的完整信息
   - **修复建议**：AI 生成的修复方案

## 第四章 漏洞管理

### 4.1 漏洞状态流转

**完整生命周期**：

```
新发现(new) → 已确认(confirmed) → 已修复(fixed) → 已验证(verified) → 关闭(closed)
      │              │                  │                  │
      └──→ 误报(false-positive) ←──────┘
```

### 4.2 漏洞确认操作

**确认漏洞**：
1. 进入漏洞详情页
2. 点击 **[确认漏洞]** 按钮
3. 填写确认备注（可选）
4. 状态变为 `confirmed`

**标记误报**：
1. 点击 **[标记误报]** 按钮
2. 输入误报原因（建议详细）
3. 状态变为 `false-positive`
4. **触发效果**：自动降低相关 Skill 精准率

**标记已修复**：
1. 开发修复后，点击 **[标记已修复]**
2. 记录修复方案（可选）
3. 状态变为 `fixed`

**验证修复**：
1. 点击 **[验证修复]** 按钮
2. 系统重新检测该漏洞
3. 若漏洞消失 → `verified`
4. 若仍存在 → 提示重新修复

### 4.3 漏洞详情解读

**详情页信息**：

| 字段 | 说明 |
|-----|-----|
| **漏洞标题** | AI 生成的简明描述 |
| **漏洞类型** | SQL注入/XSS/CSRF 等 |
| **CWE编号** | 标准漏洞分类编号 |
| **严重程度** | 高危/中危/低危 |
| **位置信息** | 文件路径 + 行号 |
| **POC代码** | 可复现的攻击代码 |
| **修复建议** | AI 生成的修复方案 |
| **发现 Skill** | 检测该漏洞的 Skill 名称 |

## 第五章 Skills 管理

### 5.1 Skill 概念说明

**Skill 定义**：
> Skill 是 AI 检测特定类型漏洞的"知识单元"，包含：
> - 检测规则（Markdown 格式）
> - 适用语言/技术栈
> - 关联漏洞模式

**Skill 类型**：

| 类型 | 来源 | 特点 |
|-----|-----|-----|
| **预置 Skill** | 系统内置 | 经过验证，精准率高 |
| **自定义 Skill** | 用户创建 | 针对特定场景 |
| **进化 Skill** | AI 自动优化 | 持续迭代改进 |

### 5.2 Skill 列表管理

**筛选与搜索**：
- **按分类**：输入验证/认证鉴权/配置安全等
- **按语言**：Java/Python/JavaScript/Go 等
- **按状态**：已启用/已禁用/私有/公开
- **关键词搜索**：Skill 名称/描述

**批量操作**：
1. 多选 Skills（勾选框）
2. 选择操作：
   - **批量启用**：激活检测能力
   - **批量禁用**：暂停使用
   - **批量删除**：移除 Skills
3. 点击 **[执行]**

### 5.3 Skill 创建向导

**快速创建**：
1. 点击 **[+ 创建 Skill]**
2. 选择创建模式：
   - **手动编写**：输入 Markdown 规则
   - **AI 生成**：描述需求，AI 自动生成
3. 填写基础信息：
   - Skill 名称（唯一标识）
   - 显示名称（中文描述）
   - 分类选择
   - 适用语言
4. 编写/编辑检测规则
5. 点击 **[保存]**

**AI 生成模式**：
```
输入示例："检测 Java Spring Boot 中的 SQL 注入漏洞，关注 MyBatis 框架"
AI 输出：完整 Skill Markdown + 测试用例建议
```

### 5.4 Skill 版本管理

**版本历史**：
- 每次修改自动创建新版本
- 支持查看历史版本内容
- 显示修改时间和操作人

**版本回滚**：
1. 点击 Skill 的 **[版本历史]**
2. 选择目标版本
3. 点击 **[回滚至此版本]**
4. 系统恢复旧版本内容

## 第六章 Skill 进化系统

### 6.1 进化原理

**智能闭环**：

```
┌─────────────────────────────────────────────────────────┐
│               Skill 精准率进化闭环                        │
├─────────────────────────────────────────────────────────┤
│                                                          │
│   漏洞标记 → 精准率计算 → 自动触发 → AI 分析 → 生成改进   │
│       ↑                                    │            │
│       │                                    ↓            │
│   回测验证 ←─ Skill 更新 ←─ 10 次重试 ←─────┘            │
│                                                          │
└─────────────────────────────────────────────────────────┘
```

**进化触发条件**：
- 精准率 < 阈值（默认 70%）
- 误报数 ≥ 最小触发数（默认 5）
- 自动监控，无需人工干预

### 6.2 进化任务管理

**任务列表**：

| 状态 | 说明 | 可执行操作 |
|-----|-----|-----------|
| **pending** | 待处理 | 手动触发分析 |
| **analyzing** | 分析中 | 查看进度 |
| **completed** | 已完成 | 查看结果、回测详情 |
| **rejected** | 已拒绝 | 人工审核、重新触发 |

**任务详情**：

1. 点击任务卡片展开详情
2. 显示信息：
   - **触发原因**：精准率过低/误报过多/手动触发
   - **误报数/确认数**：统计数据
   - **进化前精准率**：历史数据
   - **改进建议**：AI 生成的优化方案
   - **回测结果**：新 Skill 的验证数据

### 6.3 进化尝试记录

**10 次重试机制**：

| 尝试次数 | AI Prompt | 结果 |
|---------|----------|------|
| 第1次 | 基础分析 + 误报案例 | 可能失败 |
| 第2次 | + 第1次失败原因反馈 | 优化调整 |
| ... | + 累积失败反馈 | 持续改进 |
| 第10次 | 全量反馈 + 最终尝试 | 达标或拒绝 |

**反馈驱动改进**：
- 每次失败的分析结果传递给下一轮
- AI 根据失败原因调整改进策略
- 避免重复错误，提升成功率

### 6.4 回测验证标准

**达标条件**：
- ✅ **漏检数 = 0**（必须满足）
- ✅ **排除率 ≥ 50%**（误报排除能力）

**回测过程**：
1. 使用历史误报案例测试新 Skill
2. 使用历史正确发现案例验证覆盖
3. 计算漏检数和排除率
4. 双指标达标 → 确认进化成功

## 第七章 自主进化系统

### 7.1 自主学习原理

**经验提取流程**：

```
评估日志扫描 → 失败→成功序列识别 → 经验提炼 → 存入知识库 → 注入 System Prompt
```

**核心技术**：
- **序列识别**：从日志中提取"失败 → 成功"模式
- **经验泛化**：将具体案例转化为通用经验
- **自动注入**：System Prompt 自动包含已启用经验

### 7.2 经验管理

**经验列表**：

| 字段 | 说明 |
|-----|-----|
| **标题** | 经验简明描述 |
| **错误类型** | 分类标签 |
| **错误模式** | 可复现的特征 |
| **教训** | AI 提炼的避坑指南 |
| **启用状态** | 已注入/未注入 |
| **命中次数** | 实际生效次数 |

**启用/停用**：
- **启用**：自动加入 System Prompt，AI 执行时自动规避
- **停用**：移除注入，恢复原始 Prompt

### 7.3 自动提取配置

**空闲时段提取**：
- 配置时段：如 22:00-06:00
- 轮询间隔：默认 30 分钟
- 自动扫描评估日志，提取新经验

**配置参数**：

| 参数 | 默认值 | 说明 |
|-----|-------|-----|
| 启用状态 | 开启 | 是否自动提取 |
| 开始时段 | 22:00 | 空闲时段开始 |
| 结束时段 | 06:00 | 空闲时段结束 |
| 轮询间隔 | 30分钟 | 扫描频率 |

## 第八章 工作流管理

### 8.1 工作流概念

**工作流定义**：
> 工作流是评估执行的流程模板，定义了检测节点、执行顺序、角色配置。

**两种模式**：

| 模式 | 执行方式 | 适用场景 |
|-----|---------|---------|
| **DAG** | 有向无环图，拓扑顺序执行 | 全面扫描、并行检测 |
| **FSM** | 状态机，循环迭代执行 | 深度分析、闭环验证 |

### 8.2 创建工作流

**可视化编排**：
1. 进入 **[工作流管理]** 页面
2. 点击 **[+ 创建工作流]**
3. 使用可视化编辑器：
   - **节点库**：拖拽添加节点类型
   - **连线**：定义执行顺序
   - **配置**：每个节点的 Skill 选择
4. 保存并发布

**节点类型**：
- **Start**：起始节点
- **Task**：检测任务节点
- **Subtask**：子任务节点
- **End**：结束节点

### 8.3 工作流角色配置

**角色绑定模型**：
1. 选择工作流 → **[角色配置]**
2. 为每个角色指定 AI 模型
3. 示例：
   - `lead-auditor` → `claude-3-opus`（主分析师）
   - `code-reviewer` → `gpt-4-turbo`（代码审查）
   - `security-checker` → `gemini-pro`（安全检查）

### 8.4 工作流共享

**共享机制**：
1. 点击 **[创建共享]**
2. 生成共享链接
3. 其他用户可查看/复制工作流

## 第九章 漏洞模式库

### 9.1 模式库概念

**漏洞模式定义**：
> 漏洞模式是标准化漏洞分类模板，包含检测特征、修复方案、CWE 映射。

**模式结构**：
- **显示名称**：中文描述

- **适用语言**：支持的编程语言
- **检测特征**：代码模式/正则规则
- **修复建议**：标准修复方案

### 9.2 模式管理

**分类体系**：
```
注入类
  ├── SQL注入
  ├── 命令注入
  └── XPath注入
认证类
  ├── 弱密码
  ├── 会话固定
  └── CSRF
配置类
  ├── 敏感信息泄露
  └── 不安全配置
```

**模式合并**：
- 目标：减少重复，统一标准
- 操作：源模式 → 合并到目标模式
- 影响：关联 Skills 自动迁移
