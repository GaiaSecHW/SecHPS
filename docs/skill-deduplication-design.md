# Skill 去重方案设计

## 背景
- 自建算力，LLM 成本无限制
- 重点：精度高、不漏判、不错判
- 不存在完全相同的 Skill（无需哈希去重）

## 问题分析
当前方案失败原因：
1. 判断标准抽象，LLM 理解困难
2. 没有具体示例引导
3. 置信度阈值设置不合理

## 新方案：场景驱动去重

### 核心原则
**两个 Skill 是否重复 = 它们是否会在相同场景下被使用**

### 判断流程

#### Step 1: 场景提取
对每个 Skill，提取其核心使用场景：
- 目标用户是谁？
- 解决什么问题？
- 输入什么？
- 输出什么？
- 适用范围（语言、框架、漏洞类型）

#### Step 2: 场景对比
比较两个 Skill 的场景：
- 目标用户是否相同？
- 解决的问题是否相同？
- 输入输出是否重叠？
- 适用范围是否有交集？

#### Step 3: 决策
- 场景完全相同 → **重复**
- 场景部分重叠 → **相关**（需要人工确认）
- 场景完全不同 → **独立**

### Prompt 设计

```
你是一个 Skill 去重专家。请判断两个 Skill 是否真正重复。

## 判断标准

**重复的定义**：两个 Skill 在实际使用中会被用于解决相同的问题。

**判断步骤**：
1. 先分析每个 Skill 的核心功能
2. 判断它们是否会在相同场景下被使用
3. 给出结论

## Skill A
{skill_a_detail}

## Skill B  
{skill_b_detail}

## 分析要求

请回答以下问题：

1. **Skill A 的核心功能**：[一句话描述]
2. **Skill B 的核心功能**：[一句话描述]
3. **使用场景是否相同**：[是/否/部分]
4. **如果场景相同或部分相同，请说明**：[具体说明]
5. **是否存在互补关系**：[是/否，说明原因]

## 最终判断

基于以上分析，这两个 Skill：
- [ ] 完全重复（功能相同，保留一个即可）
- [ ] 部分重复（有重叠，需要合并或拆分）
- [ ] 功能互补（不同场景，都保留）
- [ ] 完全独立（无关系）

**置信度**：[0.0-1.0]
**建议操作**：[merge/keep_both/needs_review]
**详细理由**：[说明]
```

### 置信度解释
- 0.9-1.0：非常有信心是重复/不重复
- 0.7-0.9：有信心，建议自动处理
- 0.5-0.7：不太确定，需要人工确认
- 0.0-0.5：几乎无法判断

### 阈值设置
- `confidence >= 0.7` + `重复` → 自动创建重复组
- `confidence < 0.7` → 标记为待人工确认
- 所有判断结果都保存，供人工审核

## 实现要点

### 1. Skill 内容截取
- 截取前 3000 字符（保留足够上下文）
- 包含：名称、描述、触发词、主要内容

### 2. 并发控制
- 3 个并发（避免过载）
- 每批后等待 500ms

### 3. 结果存储
- 每个判断结果存入 SkillAnalysis 表
- 重复组需要人工确认后才生效

### 4. 人工审核界面
- 显示两个 Skill 的对比
- 显示 LLM 的判断理由
- 提供"确认重复"/"保留两者"/"需要更多信息"按钮

## 预期效果
- 提高召回率：不漏判真正重复的 Skill
- 降低误判：通过场景分析提高准确性
- 可追溯：所有判断有详细理由
