## 九、定时清理过期任务文件

**Commit:** `5dca3598` feat: 增加任务文件定时清理机制

### 测试步骤

> 此功能基于定时调度，需观察日志验证

1. 确认 `.env` 或 `deploy/.env.server` 配置：
   - `TASK_CLEANUP_RETENTION_DAYS=30`
   - `TASK_CLEANUP_HOUR=3`
2. 启动服务，观察日志输出

### 验收标准

| # | 检查项 | 预期结果 |
|---|--------|----------|
| 1 | 启动日志 | 日志输出 `[TaskCleanup] 首次清理将在 XX 分钟后执行（每天 3:05）` |
| 2 | 清理执行日志 | 到达定时时间后，日志输出 `[TaskCleanup] 开始扫描` 和清理结果 |
| 3 | 无过期任务 | 日志输出 `无过期任务需要清理` |
| 4 | 有过期任务 | 清理 MinIO workspace 包 + NFS 目录，数据库标记 `filesCleanedAt` |
| 5 | 已清理任务不可重跑 | 点击重跑 → 返回 `任务文件已被清理，请重新创建任务并上传文件` |
| 6 | 保留天数可配置 | 修改 `TASK_CLEANUP_RETENTION_DAYS` 后重启，日志显示新值 |

## 十、任务队列 FIFO 永久等待

**Commit:** `20175995` feat: 任务队列 FIFO 永久等待（事件驱动 + 5分钟兜底轮询）

### 测试步骤

1. 确保至少有 1 个 Worker 在线且 `maxConcurrent=1`
2. 快速连续提交 3 个任务
3. 观察任务执行顺序

### 验收标准

| # | 检查项 | 预期结果 |
|---|--------|----------|
| 1 | 任务排队 | 第 1 个任务立即执行，第 2、3 个排队等待 |
| 2 | FIFO 顺序 | 第 1 个完成后，第 2 个开始执行（先进先出） |
| 3 | 永不丢弃 | 排队任务不会超时丢弃，持续等待直到有 Worker 可用 |
| 4 | 兜底轮询 | 即使事件回调丢失，5 分钟内兜底轮询也会分发排队任务 |
